# Настройка GitHub для автоматизации (шаблон для других проектов)

Схема VYBEX, которую можно повторить: файлы в Google Drive → GitHub Actions по расписанию → результат в Drive и во внешний сервис. Без своего сервера, бесплатно.

## 1. Репозиторий
1. Новый репозиторий (приватный, если внутри есть что-то личное). Ветка по умолчанию `master` или `main`: расписание работает **только** на ней.
2. До первого коммита заполните `.gitignore`: `.venv/`, `node_modules/`, `out/`, `__pycache__/`, любые медиафайлы (`*.mp3 *.mp4 *.wav`), `.env`. Проверка: `git status` не должен показывать ни медиа, ни ключей.
3. Секреты никогда не пишутся в файлы, логи и чат. Только GitHub Secrets.
4. Коммиты и пуш: GitHub Desktop (Push origin) или `git push`.

## 2. Секреты и переменные
GitHub → репозиторий → **Settings → Secrets and variables → Actions**.
- **Secrets** (скрыты в логах): ключи API, токены, пароли. Например `BUFFER_API_KEY`, `CLOUDINARY_*`, `GDRIVE_*`, `CLAUDE_CODE_OAUTH_TOKEN`.
- **Variables** (видны, меняются без правки кода): режимы и настройки. Например `VYBEX_BUFFER=queue`, `VYBEX_POSTS_PER_DAY=3`, `VYBEX_TIMEZONE=Asia/Almaty`.
- Токен подписки Claude: в своём терминале `claude setup-token`, результат сразу в секрет (`docs/claude-author.md`).
- Секрет в workflow передаётся через `env:` нужного шага, а не глобально.

## 3. Скелет workflow (`.github/workflows/<имя>.yml`)
```yaml
name: job
on:
  schedule:
    - cron: "0 3 * * *"        # ВСЕГДА UTC: 03:00 UTC = 08:00 Алматы (UTC+5)
  workflow_dispatch:           # кнопка ручного запуска
    inputs:
      mode: { description: "режим на один запуск", default: "" }
concurrency: { group: job, cancel-in-progress: false }   # два запуска не идут одновременно
jobs:
  run:
    runs-on: ubuntu-latest
    timeout-minutes: 90
    permissions: { contents: read }
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.12", cache: pip }
      - run: pip install -r requirements.txt
      - name: Work
        shell: bash            # bash -e -o pipefail: ошибка в любой команде останавливает шаг
        env:
          API_KEY: ${{ secrets.API_KEY }}
          MODE: ${{ github.event.inputs.mode || vars.MODE || 'safe' }}   # input > variable > безопасное значение
        run: python -m app
      - name: Save results
        if: always()           # выполняется даже после ошибки, чтобы результаты и состояние не потерялись
        run: ...
```

## 4. Google Drive через rclone (без своего сервера)
- Ставится в workflow: `sudo apt-get install -y rclone`.
- Конфиг целиком через переменные окружения `RCLONE_CONFIG_GD_*` (client id/secret и refresh token из секретов), файла конфигурации в репозитории нет. Как получить токен: `docs/drive-setup.md`.
- Состояние между запусками (что уже отправлено) хранится файлом в Drive, потому что диск раннера стирается после каждого запуска. Читать состояние так: «нет файла» допустимо только когда папка/файл действительно отсутствует, ошибка Drive обязана остановить шаг (иначе потеряется защита от дублей).

## 5. Правила, которые обошлись дорого
- **Не вешайте боевой запуск на `push`.** Каждый пуш кода запустил бы генерацию и публикацию. Оставляйте `schedule` и `workflow_dispatch`.
- **Новая интеграция идёт по лестнице:** `off` → `plan` (только проверки, ничего не создаётся) → `draft` (черновик) → `queue` (боевой). Значение по умолчанию всегда безопасное; опечатка в переменной должна превращаться в `off`, а не в публикацию.
- **Не прячьте ошибки:** без `|| true`, без `exit 0` после упавшей команды, `continue-on-error` только если есть причина. Шаги сохранения результата ставьте с `if: always()`.
- **Идемпотентность:** повторный запуск не должен дублировать результат (хеш файла в состоянии, проверка «уже есть в очереди»). Запросы, создающие что-то во внешнем сервисе, не повторяйте вслепую после неясной ошибки: сначала проверьте, не создалось ли уже.
- **Расписание не точное:** задержка до часа и больше, редкие пропуски. Критичное время ставьте с запасом, при необходимости добавьте второй cron-запуск (с `concurrency`, чтобы не шли вместе).
- **Расписание отключается** в публичном репозитории после 60 дней без активности (письмо + кнопка включения на вкладке Actions). Изменения workflow-файла вступают в силу после пуша в основную ветку.
- **Лимиты:** в приватном репозитории бесплатно 2000 минут Actions в месяц; смотрите время первых запусков и умножайте на 30.
- **Часовой пояс:** cron всегда UTC. Часовой пояс для расписаний внутри кода храните в переменной.
- **Где смотреть результат:** вкладка Actions → запуск → Summary (кладите туда короткий итог через `>> "$GITHUB_STEP_SUMMARY"`).

## 6. Чек-лист перед включением
1. `.gitignore` проверен, `git status` чистый от медиа и ключей.
2. Все секреты и переменные заведены, режим по умолчанию безопасный.
3. Ручной запуск в режиме `plan`, потом `draft`, потом один боевой с минимальным количеством.
4. Результат проверен руками (в сервисе назначения), только потом включается расписание.
5. Первые 3–5 дней смотрите Summary и красные запуски.
