# Шаг Claude: карточки под смысл песни в GitHub Actions

Без него Actions подбирает карточки по ключевым словам (проще). С ним на каждую песню делается **один вызов Claude** (`pipeline/author.py`, промпт `prompts/widgets.md`): он читает строки фрагмента из whisper и пишет то же, что я делал вручную:
- подрезку фрагмента до законченной мысли (`trim`), хук-вопрос, подпись;
- карточки (вид, картинка, подписи) и уведомление острова под сюжет каждой строки.

Ответ проверяется и чистится кодом (только известные виды и поля, ограничения на длину, цвета и индексы). Любая ошибка (нет токена, плохой JSON, таймаут) = автоподбор по ключевым словам, пакет не падает. Статус каждой песни: `report.json → stages.author` и сводка шага в Actions (`claude: 8 cards, trim 2..10` или `fallback: ...`).

## Как включить (один раз)
1. В Claude Code наберите `! claude setup-token` и войдите в аккаунт. Команда выдаст длинный токен (подписка, отдельный ключ API не нужен). Токен никому не отправляйте и в чат не вставляйте.
2. GitHub → репозиторий → Settings → Secrets and variables → Actions → New repository secret: имя `CLAUDE_CODE_OAUTH_TOKEN`, значение: токен.
3. Запустите workflow (Run workflow). Шаг «Claude CLI» установит CLI, если секрет есть.

Отключить без удаления секрета: `config.json → "author": {"enabled": false}`. Модель: `"model": "sonnet"`. Локально шаг работает, если установлен `claude` и вы в нём вошли; тесты его не вызывают (`VYBEX_NO_AUTHOR=1`).

## Расход и риски
- Один запрос на ролик (~2 тыс. токенов на входе, ~1 тыс. на выходе): 3 ролика в день это 3 запроса.
- Работа на CI с токеном подписки в этом проекте **не проверялась** (локально проверено).
- Тексты строк это данные: инструкции внутри них модель не должна выполнять, а результат всё равно проходит `sanitize_widgets`.
