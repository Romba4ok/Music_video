# Шаг Claude: карточки под смысл песни в GitHub Actions

Без него Actions подбирает карточки по ключевым словам (проще). С ним на каждую песню делается **один вызов Claude** (`pipeline/author.py`, промпт `prompts/widgets.md`): он читает строки фрагмента из whisper и пишет то же, что я делал вручную:
- подрезку фрагмента до законченной мысли (`trim`), хук-вопрос, подпись;
- карточки (вид, картинка, подписи) и уведомление острова под сюжет каждой строки.

Ответ проверяется и чистится кодом (только известные виды и поля, ограничения на длину, цвета и индексы). Плохой ответ или сбой повторяется до 3 раз (`author.attempts`), после таймаута повтора нет. Только если все попытки не удались: автоподбор по ключевым словам (такие карточки похожи друг на друга), пакет не падает, а ролик помечается в `report.json → note` («Claude author failed…»). Статус каждой песни: `report.json → stages.author` и сводка шага в Actions (`claude: 8 cards, trim 2..10` или `fallback: ...`).

**Два шага: сценарий, потом картинки (2026-11-10).** Вместо одного вызова теперь два (`author.author`). Шаг 1, `prompts/scenario.md`: из текста ВСЕЙ песни Claude пишет `about`, путь песни `arc` (завязка, поворот, итог), `trim`, хук, подпись, `mood` и сценарий: по карточке на строку (`lines`, `half`, `kind`, `idea` = предмет из строки, как он меняется и как это шаг истории песни, `cap`). Код проверяет сценарий (≥3 карточки, известные виды, последняя `draw`, есть `about` и `arc`). Шаг 2, `prompts/widgets.md`: Claude рисует `svg`/`tw` строго по сценарию; если карточек, `lines`, `half` или `kind` не те (`follows_scenario`), ответ отклоняется и шаг 2 повторяется (сценарий не переписывается; всего 3 попытки). Смысл песни целиком задаёт тему, а картинки по-прежнему строятся по строчкам фрагмента. Сценарий лежит в `spec.scenario` и в `out/<дата>/scenario-N.txt`. Два вызова на ролик вместо одного.

**Анимация объектов (2026-11-09).** Рисунок `draw` теперь это один `svg` с `id` у движущихся фигур и список `tw`: что, когда и как двигается (x, y, rotation, scale, opacity, strokeDashoffset, easing, `loop`, `o`). Вместо слайд-шоу из кадров падают пальто, рисуется и стирается сердце, уходит поезд. Всё проходит `svg_safe.clean` (id только у анимированных) и `svg_safe.clean_tweens` (допустимые свойства и easing, числа в диапазоне, `id` должен быть в картинке), в авторе и ещё раз в `widgets_plan._draw`, двигает их `remotion/src/widgets/anim.ts`. Меньше двух корректных анимаций = не анимация: картинка остаётся неподвижной, парит как раньше. Старое поле `frames` по-прежнему работает, но промпт его больше не просит (до 2026-11-09 вечера промпт всё ещё просил `frames`, поэтому в опубликованных роликах картинки сменялись кадрами; исправлено в `prompts/widgets.md`). Ограничения: svg до 4500 знаков (в промпте 2500), до 30 анимаций; двигаемые фигуры без `transform`. Ручной образец: `out/2026-11-09-proskovya-anim/make_spec.py`.

**Микс карточек:** не меньше 2/3 нарисованных (`draw` с кадрами, меняются каждую секунду; у них могут быть `big` и до двух `chips` как детали приложения), шаблонных не больше трёх и разных видов, один вид не больше раза за ролик (2026-11-08: ролик целиком из шаблонов выглядел одинаково; референс «Кинолента — Баста» от 610ckbaby1). Образец по вкусу: прогон «Баста — 8800» от 2026-11-07.

**Каждый раз новое.** К каждому запросу код добавляет свежее задание (`author.variety()`, случайное, ничего не хранится): 6 случайных шаблонных видов запрещены в этом ролике, всем рисункам `draw` задан другой стиль (акварель, аппликация, мелки… только узнаваемые предметы, без абстракции), а ещё список видов, уже занятых другими роликами дня (`avoid_kinds`).

**Числа и повторы (разбор роликов 2026-11-08).** Карточки `ring`/`dots`/`counter` код оставляет, только если число `to` есть в тексте их строк цифрами (иначе удаляет; строки получают автокарточку); хук закрывает `cap` последней карточки; `ring`, `dots`, `counter`, `pair`, `search` вместе не больше раза за ролик (правило в промпте, не в коде).

**Тема, память, итоги (2026-11-08).** Claude отдаёт `mood`: `dark` (тёмный фон со свечением, светлый текст вне карточек, `spec.theme`) или `light`; если два последних ролика одной темы, промпт просит другую. После каждого ролика `batch` дописывает состав в `accounts/<acc>/cards.jsonl` (виды карточек, хук, тема, доля рисунков, число деталей); следующий запуск избегает недавних шаблонных видов. В CI файл сохранится, только если workflow его коммитит (не настроено). `python -m pipeline insights` сопоставляет `cards.jsonl` с `accounts/<acc>/views.csv` (`song,views`, вручную с профиля TikTok) и при 5+ роликах показывает медиану просмотров по теме, доле рисунков, деталям.

## Как включить (один раз)
1. В Claude Code наберите `! claude setup-token` и войдите в аккаунт. Команда выдаст длинный токен (подписка, отдельный ключ API не нужен). Токен никому не отправляйте и в чат не вставляйте.
2. GitHub → репозиторий → Settings → Secrets and variables → Actions → New repository secret: имя `CLAUDE_CODE_OAUTH_TOKEN`, значение: токен.
3. Запустите workflow (Run workflow). Шаг «Claude CLI» установит CLI, если секрет есть.

Отключить без удаления секрета: `config.json → "author": {"enabled": false}`. Модель: `"model": "sonnet"`. Локально шаг работает, если установлен `claude` и вы в нём вошли; тесты его не вызывают (`VYBEX_NO_AUTHOR=1`).

## Расход и риски
- Два запроса на ролик (сценарий ~2 тыс. токенов на входе, построение ~4 тыс.): 3 ролика в день это 6 запросов.
- Работа на CI с токеном подписки в этом проекте **не проверялась** (локально проверено).
- Тексты строк это данные: инструкции внутри них модель не должна выполнять, а результат всё равно проходит `sanitize_widgets`.
